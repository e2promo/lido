# Деплой Лидо на Vercel — пошагово

Инструкция для обычного пользователя. Без терминала и без git-команд.
Занимает примерно 30–40 минут, из них большая часть — регистрация в Supabase и ВК.

Адрес проекта: https://vercel.com/e2promos-projects/lido

---

## Что важно понять до начала

Приложение состоит из двух частей, и это главное для понимания всей инструкции:

1. **Код** живёт на GitHub. Vercel берёт код оттуда и собирает из него сайт.
2. **Данные** (диалоги, клиенты, настройки) живут в отдельном хранилище — Supabase.
   Vercel не хранит файлы между запросами, поэтому база каждый раз восстанавливается
   из Supabase и сохраняется обратно.

Если не настроить Supabase, сайт откроется, но на любой запрос ответит
`503 Хранилище не подключено`. Если не настроить ВК, диалоги будут создаваться
только в интерфейсе, но не в реальном сообществе.

## Шаг 1. Создать хранилище в Supabase

Это бесплатно.

1. Откройте https://supabase.com/dashboard и войдите (можно через GitHub).
2. Нажмите **New project**.
3. Заполните:
   - **Name**: `lido`
   - **Database Password**: придумайте пароль и сохраните его (для нашего способа он не понадобится, но пусть будет)
   - **Region**: выберите ближайший, например `Frankfurt` или `Central EU`
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.
5. Слева откройте **SQL Editor** → **New query**.
6. Вставьте целиком текст из файла `supabase/setup.sql` (он лежит в архиве) и нажмите **Run**.
   Должно появиться `Success. No rows returned`. Это создало две таблицы:
   `lido_snapshots` (данные) и `lido_locks` (защита от одновременной записи).
7. Слева откройте **Project Settings** (шестерёнка) → **API**.
   Возьмите оттуда два значения:
   - **Project URL** — вида `https://abcdefgh.supabase.co`
   - **service_role** ключ (в разделе Project API keys, нажмите **Reveal**)

> **Важно про ключ.** Нужен именно `service_role`, а не `anon`. Ключ `service_role`
> даёт полный доступ к базе — никому его не показывайте и не публикуйте.
> Он нужен только в настройках Vercel.

## Шаг 2. Создать приложение ВКонтакте и получить доступы

Нужны четыре значения. Где взять каждое — ниже.

### 2.1. ID сообщества (`VK_GROUP_ID`)

1. Откройте своё сообщество ВК.
2. **Управление** → **Настройки** → раздел **Адрес** (или посмотрите на URL:
   `vk.com/club123456789` — число и есть ID).
3. Запишите число, например `128452301`.

### 2.2. Токен сообщества (`VK_GROUP_TOKEN`)

1. В сообществе: **Управление** → **Работа с API** → **Ключи доступа**.
2. **Создать ключ**.
3. Отметьте галочками права:
   - **Сообщения сообщества** (обязательно)
   - **Управление сообществом** (нужно для чтения названия)
4. Подтвердите и скопируйте ключ. Он показывается один раз, вида `vk1.a....`

### 2.3. Секретный ключ Callback API (`VK_SECRET`)

1. В сообществе: **Управление** → **Работа с API** → вкладка **Callback API**.
2. В блоке настроек найдите поле **Секретный ключ**.
3. Придумайте строку, например `lido_secret_2026`, впишите и сохраните.
4. Запомните её — она понадобится в Vercel.

> Если оставить `VK_SECRET` пустым, приложение будет принимать любые запросы
> к вебхуку без проверки. Так делать не надо: адрес вебхука публичный.

### 2.4. Строка подтверждения (`VK_CONFIRMATION_TOKEN`)

1. На той же вкладке **Callback API** есть поле **Строка, которую должен вернуть сервер**.
2. Скопируйте её целиком (обычно длинная случайная строка).

### 2.5. Адрес сервера и типы событий

Это делается **после** деплоя на Vercel (шаг 5), потому что адрес появится только тогда.

## Шаг 3. Залить файлы в GitHub

Ваш проект лежит в репозитории, который подключён к Vercel. Заливать нужно
**содержимое архива** `lido-vercel-deploy.zip`, а не саму папку.

### Через веб-интерфейс GitHub (проще всего)

1. Распакуйте `lido-vercel-deploy.zip` на компьютере. Внутри будет папка `lido-vercel`.
2. Откройте свой репозиторий на github.com.
3. Нажмите **Add file** → **Upload files**.
4. Откройте распакованную папку `lido-vercel`, выделите **всё содержимое внутри**
   (файлы и папки `api`, `server`, `public`, `supabase` и файлы `package.json`,
   `vercel.json` и остальные) и перетащите в окно браузера.
5. Внизу нажмите **Commit changes**.

> **Проверка, без которой дальше нет смысла.** После загрузки откройте в репозитории
> папку `server`. В ней должны быть 13 файлов, включая `index.js`, `db.js`, `api.js`.
> Если папки `server` нет — приложение на Vercel упадёт с ошибкой
> `Cannot find module '../server/index.js'`. Загрузите её отдельно.

### Что НЕ нужно загружать

- `.env` — файл с секретами, в архиве его нет и добавлять не надо
- папку `data` — локальная база, на Vercel она не используется
- `node_modules` — Vercel ставит зависимости сам

## Шаг 4. Прописать переменные в Vercel

1. Откройте https://vercel.com/e2promos-projects/lido
2. **Settings** → **Environment Variables**.
3. Для каждой переменной: введите **Key** и **Value**, выберите окружение
   **Production** (можно отметить сразу все три: Production, Preview, Development),
   нажмите **Save**.

### Обязательные переменные

| Key | Что вписать | Откуда взять |
|---|---|---|
| `SUPABASE_URL` | `https://abcdefgh.supabase.co` | Шаг 1.7, Project URL |
| `SUPABASE_SERVICE_KEY` | длинный ключ `eyJ...` | Шаг 1.7, ключ service_role |
| `VK_GROUP_TOKEN` | `vk1.a....` | Шаг 2.2 |
| `VK_GROUP_ID` | `128452301` | Шаг 2.1 |
| `VK_SECRET` | `lido_secret_2026` | Шаг 2.3 |
| `VK_CONFIRMATION_TOKEN` | строка из ВК | Шаг 2.4 |

Этих шести достаточно, чтобы приложение работало и принимало сообщения из ВК.

### Необязательные переменные

Нужны, только если хотите, чтобы агент отвечал через настоящую языковую модель,
а не встроенным демо-движком.

**Вариант «Яндекс»:**
| Key | Значение |
|---|---|
| `AI_PROVIDER` | `yandex` |
| `YANDEX_FOLDER_ID` | folder id из Яндекс.Облака |
| `YANDEX_API_KEY` | API-ключ сервисного аккаунта |
| `YANDEX_MODEL` | `yandexgpt/latest` |

**Вариант «GigaChat»:**
| Key | Значение |
|---|---|
| `AI_PROVIDER` | `gigachat` |
| `GIGACHAT_CLIENT_ID` | Client ID из личного кабинета |
| `GIGACHAT_CLIENT_SECRET` | Client Secret |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` |

**Уведомления в Telegram владельцу:**
| Key | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | ваш chat id |

> Если не задать `AI_PROVIDER`, приложение использует встроенный демо-движок.
> Он работает без ключей и интернета: отвечает по базе знаний заготовками.
> Для теста подходит, для реальной работы — нет.

### Чего делать НЕ нужно

Не задавайте `PORT`, `HOST`, `DATA_DIR` — Vercel выставляет их сам.
Не задавайте `NEON_DATABASE_URL` и `UPSTASH_*` одновременно с Supabase:
если задано несколько вариантов хранилища, приоритет у Supabase, остальные
будут молча игнорироваться.

## Шаг 5. Пересобрать проект (Redeploy)

Переменные применяются только к новой сборке.

1. В Vercel откройте вкладку **Deployments**.
2. У последнего деплоя нажмите **⋯** (три точки) → **Redeploy**.
3. В окне подтверждения снимите галочку **Use existing Build Cache**, если она есть.
4. Нажмите **Redeploy** и дождитесь статуса **Ready** (1–2 минуты).

### Проверка, что всё поднялось

Откройте в браузере:

```
https://lido-<ваш-домен>.vercel.app/health
```

Должно вернуться примерно такое:

```json
{"ok":true,"service":"lido","time":"2026-11-26T16:35:10.086Z"}
```

Если вместо этого `503 Хранилище не подключено` — вернитесь к шагу 4,
проверьте `SUPABASE_URL` и `SUPABASE_SERVICE_KEY`, затем снова Redeploy.
Если `500` — откройте **Deployments** → последний деплой → **Functions** →
**Logs** и посмотрите текст ошибки.

Затем откройте сам сайт:

```
https://lido-<ваш-домен>.vercel.app
```

Вход: `demo@lido.ru` / `lido2026`.
Сразу после первого входа **смените пароль** — этот логин известен всем,
кто видел исходники.

## Шаг 6. Подключить Callback API в ВК

Теперь у вас есть рабочий адрес, и можно связать его с сообществом.

1. В сообществе: **Управление** → **Работа с API** → **Callback API**.
2. В поле **Адрес** впишите:

```
https://lido-<ваш-домен>.vercel.app/webhook/vk
```

3. Нажмите **Проверить сервер**. ВК отправит запрос, приложение вернёт строку
   подтверждения. Должно появиться «Сервер успешно ответил» или подобное.
4. Перейдите на вкладку **Типы событий** и отметьте:
   - **Входящее сообщение** — обязательно (без него диалоги не появятся)
   - **Исходящее сообщение** — чтобы ваши ответы из ВК тоже попадали в интерфейс
   - **Редактирование сообщения** — по желанию
5. Нажмите **Сохранить**.

### Проверка вживую

1. Откройте сообщество ВК с другого аккаунта (или попросите кого-нибудь).
2. Напишите в сообщения сообщества: «Здравствуйте! Сколько стоит стрижка?»
3. В течение нескольких секунд сообщение должно появиться в разделе **Диалоги**
   на сайте, а агент — ответить в ВК.

Если в ВК сообщение ушло, а в интерфейсе его нет — смотрите раздел
«Если что-то не работает» ниже.

## Если что-то не работает

### Сайт открывается, но пишет «Хранилище не подключено»

Не заданы или заданы неверно `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`.
Проверьте, что URL начинается с `https://` и не имеет слэша на конце,
что взят ключ `service_role`, а не `anon`. После правки — Redeploy.

### Ошибка 500 при открытии сайта

Откройте **Deployments** → последний деплой → **Functions** → **Logs**.
Частые причины:
- в репозитории нет папки `server` (см. проверку в шаге 3);
- в `package.json` указана версия Node ниже 22.13 — там `node:sqlite`
  работает только с флагом, и приложение падает при старте.

### В ВК сообщение пришло, в интерфейсе диалога нет

1. **Deployments** → **Functions** → **Logs**, найдите запрос к `/webhook/vk`.
   - Если в логах `403 forbidden` — не совпадает `VK_SECRET`.
     Значение в Vercel должно **посимвольно** совпадать с полем
     «Секретный ключ» в ВК. После правки — Redeploy.
   - Если запросов к `/webhook/vk` вообще нет — неверный адрес в Callback API
     или не отмечен тип события «Входящее сообщение».
2. Проверьте, что в ВК нажата кнопка **Проверить сервер** и она прошла успешно.

### Агент не отвечает в ВК, но диалог создаётся

Не задан `VK_GROUP_TOKEN`, либо у ключа нет права «Сообщения сообщества»,
либо сообщество запретило сообщения от имени сообщества.
Проверьте: **Управление** → **Работа с API** → **Ключи доступа**, права ключа.

### Диалоги пропали после перезапуска

Значит, данные не сохраняются в Supabase. Проверьте, что таблицы
`lido_snapshots` и `lido_locks` реально созданы (шаг 1.6) и что ключ —
`service_role`. С ключом `anon` запись молча не проходит.

## Что было исправлено в этой версии

Три ошибки, из-за которых прошлая версия не работала:

1. **Вебхук не читал тело запроса на Vercel.** Код читал тело только из потока,
   а Vercel передаёт его уже разобранным в `req.body`. В результате проверка
   секрета не проходила, приложение отвечало `403 forbidden`, и сообщение
   из ВК выбрасывалось. Теперь тело читается обоими способами.
2. **`.vercelignore` исключал папку `server`.** При этом `api/app.js` её
   импортирует. Функция падала с `Cannot find module`. Папка больше не исключается.
3. **Неверная версия Node.** `node:sqlite` до версии 22.13 требовал флаг
   `--experimental-sqlite`. В `package.json` теперь `>=22.13.0`.
