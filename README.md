# Лидо — ИИ-агент для ВКонтакте

**Лидо** — готовый к запуску MVP SaaS-сервиса, который подключает сообщество ВКонтакте, автоматически ведёт переписку с входящими клиентами и доводит диалог до получения номера телефона.

> Демо-доступ: `demo@lido.ru` / `lido2026`
> Приложение: `http://localhost:3000`

---

## 1. Концепция

### Проблема
Предприниматель получает сообщения в сообществе ВКонтакте, но отвечает не всегда и не вовремя. Часть клиентов уходит, так и не оставив контакт. Ручная переписка не масштабируется, а найм менеджера дорог.

### Решение
ИИ-агент «Лидо»:

1. Сразу отвечает на входящее сообщение.
2. Выявляет потребность и отвечает на вопросы по базе знаний.
3. Объясняет пользу звонка и **ненавязчиво** просит номер телефона.
4. Распознаёт номер в любом формате, нормализует и сохраняет лид.
5. Уведомляет владельца в Telegram и передаёт диалог менеджеру при необходимости.

### Принцип продукта
**Один экран — одно действие.** Никаких технических терминов в интерфейсе, настройка за 10–15 минут, всё на русском языке.

### Бренд
- **Название:** Лидо (коротко, легко произносится, ассоциируется с «лидом»).
- **Слоган:** «ИИ-агент, который доводит диалог до телефона клиента».
- **Логотип-концепция:** скруглённый квадрат indigo-градиента с белым речевым пузырём и тремя точками — символ диалога.
- **Палитра:** `#5B5BD6` (основной), `#00B894` (успех/контакт), `#171A2E` (боковая панель), `#F5F6FA` (фон), `#1F2338` (текст).
- **Шрифт:** Manrope с системным fallback.

## 2. MVP: что вошло, а что нет

**Вошло (ядро ценности):**
- авторизация и 10 экранов интерфейса;
- подключение сообщества ВК + Callback API webhook;
- настройка агента (имя, стиль, приветствие, цель, логика, ограничения, режимы);
- база знаний с FAQ;
- ИИ-переписка с управляемым сценарием;
- распознавание и нормализация телефона, согласие 152-ФЗ;
- CRM: диалоги, карточка лида, заметки, менеджеры;
- аналитика: конверсия, динамика, причины отказов;
- **экономика ИИ:** подключение моделей, цены токенов, калькулятор стоимости диалога и маржи, учёт реальных токенов;
- Telegram-уведомления, логи, тарифы.

**Не вошло сознательно (следующая итерация):**
- реальные платежи и личный кабинет биллинга;
- парсинг PDF/DOCX (в MVP — ручное добавление записей);
- интеграции с российскими CRM (АmoCRM/Битрикс24) — заложена архитектура;
- многопользовательские роли и права;
- тонкая настройка prompt chains и A/B-тесты сценариев.

## 3. Архитектура

### Фактическая реализация в этом репозитории
MVP собран на **нулевых внешних зависимостях** — это осознанный выбор для быстрого и устойчивого запуска:

| Слой | Решение |
|---|---|
| Frontend | Vanilla JS ES-модули, SPA с hash-роутингом, собственная CSS-дизайн-система |
| Backend | Node.js 22, встроенный `node:http`, REST API + Callback webhook |
| База данных | Встроенный `node:sqlite` (SQLite, WAL), файл `data/lido.db` |
| Авторизация | E-mail/пароль (scrypt),bearer-токен в `sessions` |
| VK API | `fetch` → `api.vk.com/method/*`, Callback API `/webhook/vk` |
| ИИ | Провайдер-абстракция: демо-движок / YandexGPT / GigaChat / OpenAI-совместимый |
| Очередь | В MVP синхронная обработка + SQLite как надёжный журнал; легко заменяется на Redis/BullMQ |
| Логи | Таблица `logs` + консоль сервера |
| Безопасность | секрет webhook, валидация путей статики, scrypt-хеши, whitelist полей API |
| Docker | `Dockerfile` + `docker-compose.yml` (см. ниже) |

### Рекомендуемая продакшн-эволюция (без переписывания продукта)

```
Nginx (TLS, статик) → Node API (3 инстанса) → PostgreSQL (вместо SQLite)
                          ├── Redis + BullMQ (очередь сообщений)
                          ├── VK API / LongPoll или Callback
                          ├── YandexGPT / GigaChat (российские ЦОД)
                          └── Telegram Bot API (уведомления)
Хостинг: Reg.ru / Timeweb / Selectel / Ruvds в московском ЦОД.
```

Причины смены SQLite на PostgreSQL при росте: конкурентные записи, репликация, полнотекстовый поиск, аналитические окна. API-контракт при этом не меняется.

### Структура файлов

```
server/
  index.js      HTTP-сервер, статик, webhook /webhook/vk, /health
  master.js     компании, пользователи, сессии (data/master.db)
  templates.js  9 отраслевых шаблонов агента и базы знаний
  db.js         схема SQLite, сид демо-данных, helper'ы, изоляция компаний
  api.js        REST API, авторизация, тарифы
  engine.js     конвейер обработки сообщения (ядро агента)
  ai.js         системный промпт, демо-движок, адаптеры ИИ
  phone.js      распознавание телефона, отказов, передачи менеджеру
  vk.js         VK API-клиент и разбор Callback API
  analytics.js  метрики и дашборд
  notify.js     Telegram-уведомления
  util.js       JSON, body, токены, хеширование
public/
  index.html, styles.css, app.js, lib.js
  pages/        10 экранов (dashboard, vk, agent, knowledge, dialogs,
                chat, lead, analytics, settings, testing)
tests/smoke.test.js
```

## 5. Принцип работы агента

### Базовый сценарий (11 шагов)
1. Клиент пишет сообществу → webhook `message_new`.
2. Агент приветствует (используется текст из настроек).
3. Определяет потребность по ключевым словам (стрижка, маникюр, цена и т.д.).
4. Ищет ответ в базе знаний и отвечает по делу.
5. Даёт короткую пользу (категория мастера, стерильность, время под запись).
6. Выбирает момент: после ответа на вопрос клиента, а не в первом сообщении.
7. Просит номер, объясняя выгоду: «перезвоним и подберём время».
8. При получении телефона подтверждает его в формате `+7 (916) 123-45-67`.
9. Нормализует и сохраняет в карточку лида, помечает согласие.
10. Пишет уведомление в Telegram и событие в лог.
11. При отказе — не давит, отвечает на вопрос и корректно завершает; при просьбе — передаёт менеджеру.

### Варианты для типов бизнеса (настраиваются полями «О компании», «Цель», «Логика» и базой знаний)

| Бизнес | Потребность | Польза звонка | Пример просьбы |
|---|---|---|---|
| Салон красоты | Услуга и мастер | «Мастер перезвонит и подберёт время» | «Оставьте номер — запишем на удобный день» |
| Автосервис | Модель авто, неисправность | «Диагност уточнит детали и назвал цену» | «Оставьте номер, мастер перезвонит с диагностикой» |
| Клиника | Направление, врач | «Администратор подберёт врача и время» | «Оставьте контакт — запишем на приём» |
| Недвижимость | Бюджет, район, метраж | «Риелтор пришлёт подходящие объекты» | «Оставьте номер — подберём квартиры под запрос» |
| Онлайн-школа | Курс, уровень | «Куратор пришлёт программу и дату старта» | «Оставьте номер — пришлём бесплатный урок» |
| Магазин | Товар, наличие | «Уточним наличие и доставим» | «Оставьте номер — забронируем товар» |

Все эти сценарии работают на одном движке: меняются только тексты в настройках и записи базы знаний.

## 6. Монетизация (реалистично для РФ)

| Тариф | Цена | Лимиты | Для кого |
|---|---|---|---|
| Пробный | 0 ₽, 14 дней | 1 сообщество, 100 диалогов | Знакомство с продуктом |
| Базовый | 1 490 ₽/мес | 1 сообщество, 1 000 диалогов, YandexGPT/GigaChat | Малый бизнес |
| Профессиональный | 2 490 ₽/мес | 3 сообщества, 5 000 диалогов, все провайдеры, менеджеры | Растущие компании |
| Для агентств | 7 990 ₽/мес | 20 сообществ, отдельный сервер, белый бренд | Агентства |

**Дополнительные опции (планируются):** подключение дополнительного сообщества — 990 ₽/мес; расширение лимита диалогов — 500 ₽ за 1 000; выгрузка в CRM — 1 900 ₽/мес.

**Себестоимость:** при среднем диалоге ~12 сообщений и ~4 000 токенов YandexGPT стоимость обработки ≈ 2–4 ₽ за диалог. При тарифе 2 490 ₽ и 1 000 диалогах маржинальность остаётся высокой. Демо-движок стоит 0 ₽ и позволяет запуститься без ключей.

### 6.0. Универсальность: любая компания и отрасль

Лидо — не жёстко привязан к салону красоты. Каждая компания получает **отдельное рабочее пространство** со своими настройками, базой знаний, диалогами, лидами и статистикой (отдельный SQLite-файл `data/org_<id>.db`).

- **Регистрация:** на экране входа есть «Нет аккаунта — создать компанию». Укажите название, e-mail, пароль и сферу — агент сразу настроится по шаблону.
- **9 отраслевых шаблонов:** универсальный, салон красоты, автосервис, клиника, недвижимость, онлайн-школа, магазин, кафе/ресторан, услуги и бизнес. Каждый задаёт приветствие, описание, цель, логику, ограничения и готовую базу знаний (цены, услуги, запись).
- **Переключатель компаний** в боковом меню: можно создать ещё одну компанию и переключаться между всеми без перелогина.
- **Смена сферы:** «Настройки → Компания и отрасль» — смена шаблона обновляет приветствие, логику и базу знаний; диалоги и лиды сохраняются.
- **Для каждой компании нужен свой ВК-сообщество и токен.** Callback API адрес: `https://ваш-хост/webhook/vk?org=<slug>` (без параметра используется демо-компания).

Шаблоны лежат в `server/templates.js`; программирование не нужно — всё настраивается в интерфейсе.

API: `GET /api/templates`, `POST /api/register`, `GET /api/organizations`, `POST /api/organizations`, `POST /api/organizations/:id/select`, `PUT /api/organizations/:id`.

### 6.05. Клиент сам выбирает модель ИИ

На экране **«Модели ИИ»** (раздел «Настройка агента» в боковом меню) владелец компании делает всё сам:

1. Видит 4 карточки: демо-движок, YandexGPT, GigaChat и OpenAI-совместимый API — с описанием, ценой за 1 млн токенов и статусом ключей.
2. Нажимает «Выбрать» нужную модель и вводит **свои** ключи (Client ID/Secret для Сбера, Folder ID/API-ключ для Яндекса, Base URL/ключ для другого API).
3. Нажимает «Проверить подключение» — сервер отправляет тестовый запрос к провайдеру и показывает результат.
4. Нажимает «Сохранить и включить» — агент этой компании сразу начинает отвечать через выбранную модель.

Выбор и ключи хранятся **в настройках конкретной компании**, а не глобально: в разных компаниях могут работать разные модели. Переменные окружения `AI_PROVIDER`, `GIGACHAT_*` и т.д. используются только как запасные значения, если компания ещё ничего не выбрала. Кнопка «Проверить текущую» в шапке экрана и ссылка из «Настроек» позволяют быстро диагностировать модель.

API: `GET /api/ai/models`, `POST /api/ai/test`, `PUT /api/settings/ai`.

### 6.1. Экономика ИИ и подключение моделей

Экран **«Экономика ИИ»** («Система» в боковом меню) решает две задачи:

1. **Подключение модели.** Показывает текущего провайдера, модель и статус ключей; кнопка ведёт в настройки, где вводятся Folder ID/API-ключ YandexGPT, Client ID/Secret GigaChat или Base URL/ключ OpenAI-совместимого API. Ключи можно задать и через `.env`.
2. **Расчёт экономики.** Редактируемые цены за 1 млн входных/выходных токенов для каждого провайдера (по умолчанию оценочные: YandexGPT 15/90 ₽, GigaChat 25/120 ₽, OpenAI-совместимый 90/270 ₽, демо 0/0). Калькулятор принимает число диалогов, сообщений в диалоге, средние токены на сообщение и цену тарифа, затем считает:
   - затраты в месяц и за диалог;
   - стоимость одного сообщения;
   - валовую маржу в рублях и процентах;
   - точку безубыточности;
   - сравнение всех провайдеров в одной таблице.

Кроме прогноза, сервер ведёт **фактический учёт**: каждая генерация ответа записывает в таблицу `ai_usage` провайдера, модель, входные/выходные токены и рассчитанную стоимость. У реальных API берётся `usage` из ответа, у демо-движка токены оцениваются по длине текста. На экране показываются расход за 30 дней, разбивка по моделям и динамика по дням.

API: `GET /api/economics`, `POST /api/economics/calculate`, `PUT /api/settings/aiPricing`.

## 7. Запуск

### Быстрый старт (без установки зависимостей)

Требуется **Node.js 22.5+** (встроенный `node:sqlite`).

```bash
cd ai_bot
node server/index.js
```

Откройте `http://localhost:3000`, войдите как `demo@lido.ru` / `lido2026`.

### Публикация на GitHub + Vercel (полностью в облаке)

**Архитектура.** Всё работает внутри Vercel. Serverless-функция на каждом запросе восстанавливает SQLite-файлы из внешнего хранилища во временную папку `/tmp`, выполняет обычный бэкенд и сохраняет изменения обратно. Хранилищем может быть **Supabase** (бесплатный тариф), **Neon Postgres** или **Vercel KV / Upstash Redis**. Клиенты заходят только на ваш `*.vercel.app` — отдельный сервер не нужен.

```
Браузер клиента → Vercel: статика + /api/* и /webhook/vk (serverless)
                       ↓ снимки SQLite
   Supabase (SUPABASE_*) / Neon (NEON_DATABASE_URL) / Vercel KV
                       ↓
                 VK API / GigaChat / Telegram
```

Для защиты от одновременного изменения базы используется короткая блокировка в хранилище.

**1. GitHub**

```bash
cd ai_bot
git init
git add .
git commit -m "Лидо — ИИ-агент для ВКонтакте"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

`.env`, `data/` и ключи в репозиторий не попадают (`.gitignore`). В архиве есть `LICENSE`, `SECURITY.md`, CI и все конфиги deployment.

**2. База (достаточно одного варианта, у всех есть бесплатный тариф)**

*Вариант А — Supabase (рекомендуется):*
1. Создайте проект на https://supabase.com/dashboard (Free tier).
2. В **SQL Editor → New query** вставьте содержимое файла `supabase/setup.sql` и нажмите **Run**. Он создаст таблицы `lido_snapshots` и `lido_locks`.
3. В **Settings → API** скопируйте:
   - **Project URL** → переменная `SUPABASE_URL` (например `https://abcdefgh.supabase.co`);
   - **service_role key** → переменная `SUPABASE_SERVICE_KEY` (нажмите «Reveal»; это секрет, никуда его не публикуйте).
4. Добавьте обе переменные в Vercel → Environment Variables → Production.

*Вариант Б — Neon Postgres:*
1. Создайте проект и базу в Neon, выберите Free tier.
2. В **Connection Details** скопируйте Connection String вида `postgresql://user:pass@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
3. Добавьте его в Vercel как переменную `NEON_DATABASE_URL`. Таблицы создадутся автоматически.

*Вариант В — Vercel KV (Upstash):*
1. Vercel → **Storage → Create Database → KV (Upstash)** → создайте и подключите к проекту.
2. Vercel автоматически добавит `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (поддерживаются алиасы `KV_REST_API_*`).

Если задано несколько вариантов, приоритет: `SUPABASE_*` → `NEON_DATABASE_URL` → Upstash.

**3. Vercel (проект)**

1. **Add New → Project** → импортируйте GitHub-репозиторий.
2. Framework Preset: **Other**. Команда сборки не нужна — всё описано в `vercel.json` и `vercel-build` в `package.json`.
3. В **Project Settings → General → Node.js Version** выберите **22.x** (нужен встроенный `node:sqlite`).
4. В **Environment Variables** добавьте переменные модели и интеграций:
   - `AI_PROVIDER=gigachat`
   - `GIGACHAT_CLIENT_ID`, `GIGACHAT_CLIENT_SECRET` (ключи Сбера)
   - `GIGACHAT_MODEL=GigaChat`, `GIGACHAT_SCOPE=GIGACHAT_API_PERS`, `GIGACHAT_TLS_INSECURE=1`
   - при необходимости `VK_GROUP_TOKEN`, `VK_GROUP_ID`, `VK_SECRET`, `VK_CONFIRMATION_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
5. Deploy → откройте `https://<ваш-проект>.vercel.app`, вход `demo@lido.ru` / `lido2026`.
6. Callback API ВК: `https://<ваш-проект>.vercel.app/webhook/vk?org=<slug>`.

**4. Проверка**

- `https://<vercel>/health` → `{"ok":true,...}`;
- `https://<vercel>/api/templates` → 9 шаблонов;
- создание компании → её диалоги сохраняются после перезапуска функции (снимки хранятся в Neon/KV и переживают «холодный старт»).

Ограничения: бесплатные тарифы Neon и KV имеют лимиты на размер и трафик; при высокой нагрузке вынесите бэкенд на постоянный сервер или используйте платный план. Для локальной разработки `lido-deploy.zip` по-прежнему запускается через `node server/index.js`.

### Подключение ВКонтакте (продакшн)

1. В сообществе: **Управление → Работа с API → Ключи доступа**. Создайте ключ с правами «Сообщения» и «Управление сообществом».
2. Там же включите **Callback API**, укажите адрес `https://ваш-домен/webhook/vk`, строку подтверждения и секретный ключ.
3. В Лидо: экран «Подключение ВК» → вставьте токен, ID сообщества, секрет и строку подтверждения → «Сохранить» → «Проверить соединение».
4. Убедитесь, что ответы идут от имени сообщества: агент отвечает через `messages.send` с `group_id`.
5. Альтернатива — LongPoll (`groups.getLongPollServer` + `groups.getLongPollHistory`), если Callback недоступен.

**Двусторонняя синхронизация с ВК (реализовано):**
- `message_new` → сообщение сохраняется в диалог софта с VK ID; повторные события с тем же ID игнорируются;
- ответ ИИ отправляется в ВК через `messages.send` **и** сохраняется локально со статусом «✓ Отправлено в ВК»;
- ответ менеджера из окна переписки также уходит в ВК и дублируется в истории;
- при первом обращении подтягиваются последние 30 сообщений ВК; кнопка «История ВК» в диалоге повторяет импорт;
- при ошибке отправки сообщение остаётся в истории с красной пометкой и текстом ошибки.

Токен можно задать либо в экране «Подключение ВК» (сохраняется в локальной БД), либо через `VK_GROUP_TOKEN` в `.env` — переменная имеет приоритет. Без токена работает демо-режим: переписка видна в софте, но в сообщество ничего не отправляется.

### ИИ-провайдеры

- **Демо-движок** — по умолчанию, работает офлайн, следует сценарию и базе знаний.
- **YandexGPT** — нужен Folder ID и API-ключ из Яндекс.Облака. Endpoint прописан в `server/ai.js`.
- **GigaChat** — Client ID/Secret, OAuth через `ngw.devices.sberbank.ru`. На российском сервере может потребоваться корневой сертификат НУЦ.

**Подключённая модель (GigaChat).** В текущем окружении реальная модель Сбера включена через `.env`:

```env
AI_PROVIDER=gigachat
GIGACHAT_CLIENT_ID=<ваш Client ID>
GIGACHAT_CLIENT_SECRET=<ваш Client Secret>
GIGACHAT_MODEL=GigaChat
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_TLS_INSECURE=1
```

Особенности реализации:
- если `Client Secret` уже является base64-строкой вида `id:secret` (как в выданном Сбером ключе), он используется напрямую в заголовке `Basic`; иначе кодируется `base64(clientId:secret)`;
- запросы к доменам Сбера идут через отдельный HTTPS-агент. Флаг `GIGACHAT_TLS_INSECURE=1` отключает проверку сертификата **только** для двух эндпоинтов GigaChat — это нужно, пока не установлен корневой сертификат НУЦ России. В продакшене установите сертификат и поставьте флаг `0`;
- токены берутся из поля `usage` ответа GigaChat и попадают в «Экономику ИИ»;
- если модель возвращает ответ не в JSON, агент всё равно добавляет естественную просьбу оставить номер из настроек — цель диалога не теряется.

⚠️ Ключи хранятся только в `.env` (файл в `.gitignore`) и не попадают в код, демо-БД или `standalone.html`. Поскольку секрет был передан открытым текстом, рекомендуется перевыпустить его в личном кабинете Сбера перед публикацией продукта.
- **Другая модель** — любой OpenAI-совместимый `chat/completions` endpoint.

Если реальный провайвер недоступен, агент автоматически падает обратно на демо-движок и пишет ошибку в лог.

## 8. Соответствие законодательству РФ

- Интерфейс, ответы и документы — на русском языке; валюта — рубль.
- 152-ФЗ: согласие фиксируется в карточке лида; текст и версия политики настраиваются в «Настройках».
- Агент собирает **только** номер телефона, который клиент написал сам. Не запрашивает паспорт, адрес, дату рождения.
- Запрещённые темы настраиваются (политика, религия, диагнозы).
- Данные хранятся в SQLite на вашем сервере; срок хранения настраивается (по умолчанию 90 дней).
- Webhook защищён секретным ключом; пароль хешируется через scrypt.
- Для продакшена: HTTPS, российский хостинг в ЦОД на территории РФ, политика обработки персональных данных на сайте сообщества.
